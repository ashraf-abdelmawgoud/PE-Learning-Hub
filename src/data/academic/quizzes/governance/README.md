# دليل حوكمة واعتماد الأسئلة الأكاديمية (Quiz Governance)
## منصة OloomSport — علوم الرياضة

يوثق هذا الدليل البنية المعمارية والإجرائية لحوكمة واعتماد أسئلة التقويم الأكاديمي في منصة OloomSport بما يضمن استقلالية المنصة كلياً كبنية ثابتة (100% Static Web Architecture) مستضافة على Cloudflare Pages، بدون أي تكاليف تشغيلية أو خوادم خلفية.

---

### 1. المبادئ الحاكمة الأساسية

1. **بنية ثابتة كلياً (Pure Static):** لا خوادم، لا قواعد بيانات، لا خدمات Workers أو Functions أو D1/KV، ولا مصادقة خارجية.
2. **حوكمة خارج الخط (Offline Academic Workflow):** تتم المراجعة والتحكيم خارج بيئة التشغيل من قبل أساتذة ومحكمين أكاديميين متخصصين.
3. **منع النشر غير المعتمد قطعياً:** يُحظر بناء أو تصدير أي سؤال بوضع `draft` أو `under_review` أو `rejected`.
4. **التجزئة التوافقية القطعية (SHA-256 Content Hash):** أي تغيير في نصوص الأسئلة أو الخيارات أو الإجابات أو التفسيرات يُبطل الهاش ويوقف البناء (Build Failure).
5. **استثناء أسئلة الفصل الأول التجريبية:** تظل تعمل بتجربتها الحالية دون تزييف أو توليد بيانات اعتماد مصطنعة لها.

---

### 2. مراحل دورة الاعتماد (Stages A–E)

- **المرحلة أ (Stage A — Academic Draft):** إعداد بنك الأسئلة وفق المادة الأكاديمية المعتمدة وتخزينه في مجلد `drafts/` بعيداً عن مسارات الاستيراد الإنتاجية.
- **المرحلة ب (Stage B — Academic Review):** فحص دقيق من المراجع الأكاديمي يشمل الصياغة، صحة الإجابة، المشتتات، دقة التفسير، والمستوى المعرفي.
- **المرحلة ج (Stage C — Explicit Approval):** الاعتماد الصريح وتوثيق اسم المحكم وتاريخ الاعتماد والمرجع الأكاديمي الدقيق.
- **المرحلة د (Stage D — Technical Publication):** نقل البنك المعتمد إلى `approved/` وتسجيله في `QUIZ_PUBLICATION_MANIFEST` مع هاش المحتوى الصارم.
- **المرحلة هـ (Stage E — Local Student Delivery):** تسليم الأسئلة للطالب عبر المكونات الحالية (`QuizBlockView`) والتقييم محلياً في المتصفح بنسبة 100%.
